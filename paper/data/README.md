# Development-journey data

Generated by `paper/scripts/journey_data.jl` from the worktree root:

```
julia --project=. paper/scripts/journey_data.jl
```

The script uses only the Julia standard library and shells out to `git` and `gh`.
Every number comes from git, gh or a committed CSV.
The command behind each table is quoted in the script next to the code that runs it.
Nothing is estimated.

## commits_weekly.csv

One row per ISO week (Monday start) from the root commit of `main` (19 May 2026) to the week the script runs.

- `n_commits_*`: first-parent commits on `origin/main`, by author date.
- `n_prs_merged_*`: pull requests merged into the repository, by merge date, from `gh pr list --state merged`.
- `human`: git emails or GitHub logins of seabbs, sbfnk, kathsherratt and SamuelBrand1.
  Commits by "Sam Abbott" with `contact@samabbott.co.uk` or `s.e.abbott12@gmail.com` are human.
- `agent`: seabbs-bot (`signin@samabbott.co.uk`, including the "Sam Abbott (bot)" author name), sbfnk-bot, and commits authored as "Claude".
- `other`: dependabot.
  The columns are additive, so human plus agent plus other is the weekly total.

## code_size.csv

One row per release tag, v1.0.0 to v2.1.0, including the capitalised V1.13.1 and V2.0.0 as they exist on the remote.
The date is the committer date of the tagged commit.
Line counts are from `git show <tag>:<path>` over `git ls-tree -r <tag>`, without checking out.

- `loc_src`: lines in `src/**/*.jl`.
- `loc_models`: lines in `src/models/**/*.jl` (zero before v1.2.0, when the models lived in the literate page).
- `loc_test`: lines in `test/**/*.jl`.
- `loc_docs_pages`: lines in `docs/examples/**/*.jl`, or `docs/pages/**/*.jl` where that exists at the tag (it never does in this range).
- `n_streams_fitted`: the number of observation-stream slots of `bvd_joint` at that tag.
  An observation submodel is a `@model function` defined in `src/models/observations.jl` at that tag.
  At v1.0.0 and v1.1.0 all models live in `docs/examples/analysis.jl`, so the set is the one v1.2.0 moved into `observations.jl` (exports, deaths, cases, exports deaths, export detection timing).
  A slot is a keyword argument of `bvd_joint` whose default is an observation submodel (`deaths = deaths_model`), counted once per slot even when two slots share a default (the v2 case and death province compositions).
  An observation submodel called directly in the body (`exports_deaths_model(...)`) adds one unless it is already a slot or a slot default.
  Comment lines are stripped first.
  A slot fitted on only one branch of an `if` still counts (v1.3.0 scores either the cumulative or the daily exports slot), so the value is the number of stream slots the joint can score, not the number scored in any one fit.

## releases.csv

Read from `data/released_estimates.csv` in the repository, whose columns are `tag, date, model, median, lo30, hi30, lo60, hi60, lo90, hi90`.
The `results-` prefix is stripped from the tag.
`date` is that file's date column, the data cut-off of the release, not the tag's commit date (which is in `code_size.csv`).
`model_version_label` maps the file's `model` column: `integral` to closed-form, `renewal` to renewal, and `patch` or `province` to provincial.
The file covers v1.0.0 to v1.6.0 only, so no later release has a headline row here.

## data_events.csv

Transcribed from `paper/.notes/steering-and-data.md` section 4 and `paper/.notes/model-timeline.md` section 2g.
Only events with a URL and a change to what the model fits are kept, at most 15.
`sitrep` is the situation report number where the notes give one.
`human_decision` is yes when the notes cite a human comment or approval on that event.

## fit_cost.csv

Copied verbatim from the bodies of PRs #656, #716, #717, #810, #837 and #856 and from the github-actions "Benchmark comparison vs main" comments on #810, #837 and #856, read with `gh pr view <n> --json body,comments`.
`arm` says which side of the PR's own comparison the number is.
`model` says what was timed, because the shapes differ: the production joint at the fit's data, a small synthetic joint, or the CI benchmark suite's synthetic joint.
A cell is empty where the source records no number.
The #717 after arm is recorded in the PR only as a ratio, which is in `note`.
The #837 body mentions "a ~14 ms joint gradient" as an approximate context figure and says none of its measurements is a joint-gradient measurement, so it is not a row.
Only #716 records a fit wall-clock (320 minutes for the headline patch fit job).

## release_estimates.csv

Generated by `paper/scripts/release_estimates.jl` (`julia --project=. paper/scripts/release_estimates.jl`), one row per release tag in `code_size.csv`, v1.0.0 to v2.1.0.
For each tag the script downloads `observations.toml`, `posterior_summary.csv` and `posterior_draws.csv` from the `results-<tag>` GitHub release into `paper/data/release/results-<tag>/` (git-ignored).

- `tag_date` is the tag's commit date from `code_size.csv`.
- `cutoff` is `as_of_date` in the release's `observations.toml`, the data cut-off of the fit.
- `model_version` is closed-form for v1.0.0 to v1.3.0, renewal for v1.4.0 to v1.18.0 and provincial for V2.0.0 and v2.1.0.
- `lower90` and `upper90` are the `Lower 90%` and `Upper 90%` columns of the headline row of `posterior_summary.csv`.
- `median` is the median of the same column of `posterior_draws.csv`, the thinned draws the release publishes, because `posterior_summary.csv` has no median column.
  This is the definition `scripts/refresh_releases.jl` uses for `data/released_estimates.csv`, and the two agree on every release that file covers (v1.0.0 to v1.6.0).
- `quantity` names the headline row: `C_T` from v1.4.0, `cumulative_cases` before, which is the closed-form model's name for the same quantity.
  The v1.3.0 release also publishes a separate `cumulative_infections` row; the headline row is the one `cumulative_cases_by_stream.csv` and the repository script call `joint`, so `cumulative_cases` is used.
- All three numbers are rounded to whole infections.

v1.11.0, v1.13.0 and v1.14.0 have no `results-<tag>` release on GitHub, so their rows carry the tag date and model version with empty numbers.
No value is estimated for them.
